# deep-plan field log — 真實使用的累積紀錄

> **與 `evals.md` 的分工**：`evals.md` 記的是**受控 eval**（有 oracle、有 fixture、可重跑、可比較兩臂）；
> 本檔記的是**真實使用**（無 oracle、一次性、觀察窗只有當下）。混在一起會讓那份 oracle 檔繼續膨脹，
> 而且兩者回答的問題不同。同一次執行同時出現在兩邊**不算重複**——`evals.md` 那側記的是 eval fixture
> 的狀態變更（如「P4 為何不登記」），本檔記的是使用面數據。
>
> **本檔不是 oracle**，但仍**不從 `SKILL.md` 連結**——runtime 不需要知道自己被記錄。

## 為什麼要有這個檔

每次執行裡，**幾乎所有東西事後都補得回來**：計畫檔全文在 `docs/plans/`（已 commit）、findings 在 PR body
與計畫的修訂痕跡、輪數與 commit hash 在 git。

**補不回來的只有一個：「這條 finding 如果沒審，會不會真的 ship 出去？」**

那是反事實判斷，只有在**剛實作完、還記得自己原本會怎麼寫**的當下答得出來。三個月後回看同一份 findings，
每條都會顯得有道理——**那正是條件式 approve 的長相**，而本 skill 存在的理由就是不採信那個外觀。

## 紀錄紀律

- **寫入時機是 ship 時，不是審完時**——「會 ship 的」要等實作完才答得出來。
- **觸發判準機械化**：這批含走過 `/deep-plan` 的 `docs/plans/*.md` → 補一段。
- **不記**：逐條 findings（會與計畫檔、PR body 漂移）、reviewer 原文、沒有數字支撐的「感覺有沒有用」。
- **`改動是否寫進權威檔` 這欄是為了日後分辨哪些結論可以外推**——dotfiles 的樣本會系統性偏向「是」。

模板：

```
### YYYY-MM-DD · <一句話情境>
計畫: <路徑> · <模型> · N=? · ? 輪 · 改動是否寫進權威檔: 是/否
findings: 第一輪 ? blocking → 第二輪 ? 復發 + ? 新
**會 ship 的: ?/?** — 逐條列出是哪幾條
成本: ~?? 萬 token / ?? 分 · 實作本身 ?? 分
一句話: <這次唯一值得記的觀察>
```

## 累積結論

> 每條標明**證據強度**。本 repo 的規則是：動 skill 規則要同情境實測到行為分歧、且必須在**樓層模型**上量。
> **本檔的條目多為 N=1 的真實觀察，只到「值得查」，不構成改規則的授權。**

### C1 — 何時值得跑：看「會不會產生無法從 diff 反推的宣稱」

**不是看 repo，也不是看變更大小。**

- **值得跑**：skill body、`CLAUDE.md`／`AGENTS.md`、`testing-contract.md`、STATUS.md 的判準、共用 fixture／eval。
  這些地方寫錯一個「為什麼」，**測試全綠、diff 看起來完美**，然後每個後續 session 都繼承它。
- **不值得跑**：`scripts/render-ssh-config.sh`、`inventory.sh` 解析、setup 腳本、`shell/functions.sh`。
  這些**測試就是 oracle**，錯了會紅；事後 `/deep-review` 更便宜且抓同一類東西。

⚠️ **dotfiles 的命中率會系統性偏高**（文件即產品，一次改動出貨的 prose 比 bash 多）。那是「在這裡該用」的
理由，**不是**外推到一般應用程式 repo 的理由——那類 repo 的 oracle 在測試裡，本 skill 的利基相對就窄。

**證據**：R1 的 3/9 全落在文件宣稱層，零條純程式碼（N=1）。

### C2 — 第二輪不能砍，但它審的是處置而非計畫

兩份獨立資料都指向第二輪有不可替代的產出：

- `evals.md` 的 **E3**（受控，樓層模型）：第二輪 (a) 重述 0 條、(b) 處置引入 3 條、(c) 第一輪沒挖到的 2 條，
  **含唯一的阻斷級**。
- **R1**（真實，Opus）：第二輪 0 復發 + 2 條新 blocking，兩條都真實。

⇒ **「小變更走單輪」這條提案已自我推翻**，不要再提。

同時看清它的真實職能：第二輪找到的多半不是原計畫的問題，是**處置新寫進去的論證**（R1 那兩條都是
Step 4 修訂時才產生的）。**推論**：處置若只是刪行、沒新增論證，第二輪期望值低；處置若寫了新理由，
它守的是一個真實的洞。

**連帶結論**：N=2 是 E1 量過的下限（N=3 多出來的全是嚴重度分歧、不是新問題），第二輪不能砍
⇒ **4 次 reviewer 執行是這個設計的地板，成本降不下來**。剩下唯一的槓桿是模型層級（見 C3）。

**證據**：E3 為受控成對；R1 為 N=1 真實觀察。兩者方向一致。

### C3 — 模型層級是唯一未動的降本槓桿，但它同時是可比性問題

R1 跑在 **Opus**（session 模型），而全部 evals 校準在 **Sonnet**（樓層模型）。兩個後果性質不同：

1. **成本** — 這是唯一還沒動過的槓桿（第二輪與 N 都動不得）。
2. **可比性** — 強模型會自己補上規則要求的行為 ⇒ **跑在 Opus 的任何觀察都不能拿來判「某條規則有沒有作用」**。

⇒ 與 N 的預設值同一類：**要刻意做的參數決定，不該在檢討裡順手改**。已記入 `docs/backlog.md`。
